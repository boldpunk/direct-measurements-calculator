# MebelFlow

Платформа управления мебельным производством — от заказа до сдачи.

MebelFlow помогает мебельным студиям (например, Sobirov Mebel, Molly.uz)
управлять заказами, контролировать внутреннее производство и аутсорс,
отслеживать переделки и видеть прибыль по каждому заказу.

Репозиторий состоит из двух частей:

- **Клиент** (корень репозитория) — одностраничное приложение на чистом
  JavaScript (Vite), хэш-роутинг.
- **Сервер** (`/server`) — REST API на Express + PostgreSQL (Prisma) с
  авторизацией по email/паролю (JWT). Данные хранятся в базе на сервере и
  доступны всем сотрудникам, вошедшим в систему, с любого устройства.

## Возможности MVP

Рабочий процесс: **Клиент → Заказ → Расходы → Производство → Оплата →
Установка → Прибыль**.

- **Заказы** — карточка заказа (клиент, адрес, ответственный, статус,
  дедлайн с «Осталось N дней» / «Просрочен на N дней»), поиск, фильтры
  (активные / просроченные / не оплачены / завершённые) и сортировка;
  на мобильных список отображается карточками, не таблицей.
- **Оплаты** — история платежей по заказу вместо одного поля
  «предоплата»; получено и остаток считаются автоматически.
- **Материалы** — построчно, с единицей измерения (шт./лист/м/м²/кг/
  комплект), сумма считается автоматически.
- **Аутсорс, зарплаты, прочие расходы** — динамические списки расходов
  вместо фиксированных полей.
- **Финансы заказа** — автоматический расчёт себестоимости, прибыли и
  маржи; ничего не считается вручную.
- **Клиенты** — карточка клиента с историей заказов, общей суммой и
  задолженностью.
- **Производство** — канбан-доска по статусу заказа (Замер → Дизайн →
  Согласование → Материалы → Производство → Сборка → Установка →
  Готов) с перетаскиванием карточек и запасным вариантом — выбором
  статуса из списка (для мобильных).
- **Этапы** — отдельный, более детальный пайплайн из 11 технических
  этапов (продажа → замер → проектирование → проверка → аутсорс
  распил/кромка → доставка → присадка → столярка → покраска → сборка →
  сдача) с ветвлением после «Присадки», виден на карточке заказа.
- **Доска «Столярка»** — канбан-доска производственных задач мастеров
  (ожидает / в работе / проверка / готово) с приоритетами и дедлайнами.
- **Задачи** — общий список задач (сегодня / просроченные / предстоящие
  / выполненные), отдельно от производственных задач «Столярки».
- **Переделки** — при создании переделки автоматически создаётся задача
  с приоритетом «Срочно», привязанная к заказу.
- **Аутсорс-партнёры** — партнёры по распилу, кромке и покраске с
  рейтингом и средним сроком выполнения.
- **Уведомления** — просроченные заказы, дедлайны «завтра», незакрытая
  задолженность и просроченные задачи — колокольчик в шапке.
- **Дашборд** — активные/просроченные заказы, к оплате, выручка,
  прибыль, ближайшие сроки, заказы по статусам.
- **Мобильная навигация** — нижняя панель (Главная / Заказы /
  Производство / Задачи / Ещё) плюс выдвижное боковое меню.
- **Сотрудники** — роли, активные задачи; новых сотрудников можно сразу
  наделить доступом (email + пароль).
- **Настройки** — компания, валюта, буфер между этапами.
- **Вход по email/паролю** — все данные привязаны к серверу, а не к
  браузеру; открыть систему можно с любого устройства под своей учётной
  записью.

## Стек

**Клиент**
- [Vite](https://vitejs.dev/) — сборка и dev-сервер.
- Чистый JavaScript (без фреймворков), хэш-роутинг.
- Font Awesome — иконки, Google Fonts (Inter) — шрифт.

**Сервер** (`/server`)
- Express — REST API.
- PostgreSQL + [Prisma](https://www.prisma.io/) ORM.
- JWT (email/пароль, bcrypt) для авторизации.

## Запуск

### 1. База данных и сервер

Нужен локальный PostgreSQL (или любой доступный по `DATABASE_URL`).

```
cd server
npm install
cp .env.example .env       # укажите DATABASE_URL и JWT_SECRET
npm run prisma:migrate     # создаёт таблицы
npm run seed                # заполняет демо-данными и учётными записями
npm run dev                 # API на http://localhost:4000
```

После `npm run seed` можно войти под любым из сотрудников, например:

```
email: ivan@mebelflow.uz
пароль: mebelflow123
```

(email каждого сотрудника — `<имя_на_латинице>@mebelflow.uz`, пароль у
всех демо-сотрудников одинаковый — `mebelflow123`; смените в реальном
использовании).

### 2. Клиент

В отдельном терминале, из корня репозитория:

```
npm install
cp .env.example .env       # VITE_API_URL, по умолчанию http://localhost:4000
npm run dev
```

Приложение откроется на `http://localhost:5173`. Сборка для продакшена:

```
npm run build
npm run preview
```

### Известные ограничения MVP

- Клиент кеширует данные в памяти и обновляет их на сервере в фоне
  (оптимистичное обновление интерфейса); список заказов и т.п. не
  обновляется в реальном времени у других открытых вкладок — только при
  следующей загрузке страницы.
- Пароль сотруднику можно задать только при создании (в форме
  «Добавить сотрудника»); смена пароля и сброс пароля пока не
  реализованы.
